# Agent Operating Guide

> Read this before your first command in this repository. It is the map of what is runnable, what is
> blocked, and who holds each blocker. Governance lives in [`AGENTS.md`](../../AGENTS.md) and
> [`docs/engineering/CONSTITUTION.md`](../engineering/CONSTITUTION.md); this page is the operational
> companion — it answers "what can I actually do right now?" without guessing.

## 1. Boot sequence

```sh
npm run preflight      # capability and credential matrix; prints no secret values
npm ci                 # if node_modules is absent
```

`preflight` is the fastest way to avoid wasting a run. It reports, per capability, `RUNNABLE` or
`BLOCKED` with the reason, and for credentials it prints only **present/absent**. Never infer that a
credential exists because a gate passed earlier; run `preflight`.

## 2. Capability matrix

| Capability | Command | Requires | If blocked |
|---|---|---|---|
| Type check | `npm run lint` | node | — |
| Unit tests | `npm run test:unit` | node | — |
| Doc links | `npm run check:docs` | node | — |
| Production build + artifact gate | `npm run build` | node, valid `VITE_*` or demo mode | — |
| Database, RLS, booking RPC | `npm run verify:db` | docker daemon | start Docker |
| Six browser journeys, hermetic | `npm run test:e2e:hermetic` | docker, supabase CLI, Playwright chromium | `npx playwright install chromium` |
| Negative controls | `npm run verify:controls` | docker, chromium | as above |
| Backup → restore → RLS, local source | `npm run rehearse:restore` | docker | start Docker |
| Backup → restore → RLS, **hosted source** | `npm run rehearse:restore:hosted` | docker **and** `SOURCE_DB_URL` | owner-held credential; see §3 |
| Push workflow files | `git push` | `gh` token with `workflow` scope | `gh auth refresh -s workflow` |

Everything except the last two rows runs with **no production credential** and is safe to run on any
machine. That is deliberate: the CI `e2e` job runs the same hermetic suite and needs no secrets.

## 3. Credential and secret map

| Variable | Purpose | Holder | How it is injected | Never |
|---|---|---|---|---|
| `SOURCE_DB_URL` | PostgreSQL URL for the live dump/restore rehearsal | Repository owner | `run-with-ops-secrets.sh` from `~/.config/stitchflow/ops.env` (mode 600) | In a commit, an issue, CI, a log, an evidence file, a `VITE_*` var, or Vercel |
| `VITE_SUPABASE_URL` / `VITE_SUPABASE_PUBLISHABLE_KEY` | Browser → PostgREST | Public by design | `.env.local` (gitignored) and the Vercel environment | — |
| `STITCHFLOW_E2E_*` pilot identities | Hosted browser journeys | Operator | `.env.pilot` (gitignored, mode 600, generated by `npm run seed:pilot`) | In a commit or an evidence file |
| `.env.test` | Hermetic local stack | Public, local-only | Tracked; runner injects the generated anon key into `.env.test.local` | A real credential of any kind |
| Service-role key | Admin scripts (`scripts/e2e/seed-local.mjs`) | Never stored in this repo | Fetched at run time from the local stack's status output | In `VITE_*`, in CI, in a log |

**There is no server in this product.** It is a static SPA calling Supabase PostgREST directly. So
there is no legitimate "server-side" home for the database password: a Vercel environment variable
would ship it to a build system that never uses it, and would widen the blast radius for nothing. The
rehearsal is an operator action, and its credential lives on the operator's machine.

### Adding the live-restore credential

Run on the operator machine only. The value is typed at a hidden prompt, is never echoed, and never
enters shell history:

```sh
npm run ops:set-source-db
```

Paste the **PostgreSQL** URI: Supabase → Project Settings → Database → Connection string (URI). It
must start with `postgresql://` and use the direct host (`db.<ref>.supabase.co:5432`) or the session
pooler on `:5432`. The transaction pooler on `:6543` cannot serve `pg_dump`; the script rejects it,
rejects the HTTPS API URL that sits next to it in the dashboard, and rejects a URI missing a user,
password, host, or database name. A rejected value writes nothing.

Then, and only then:

```sh
npm run preflight                      # SOURCE_DB_URL now reported present
npm run rehearse:restore:hosted         # exits 2, not 1, if the precondition is still missing
```

The wrapper distinguishes **exit 2** (a precondition is missing — not evidence the gate works) from
**exit 1** (a gate rejected its input). Do not report an exit-2 run as a passing rehearsal.

### Adding an application secret (Vercel)

Only for values the running app needs. The value comes from a hidden prompt and is piped to the CLI,
so it never appears in history or in process arguments:

```sh
read -rsp 'value: ' v; echo
printf '%s' "$v" | vercel env add NAME production
unset v
vercel env ls production
```

A `VITE_*` variable is baked into the browser bundle and is public. It may hold a publishable key,
never a service-role key, a password, an access token, or a database URL. The build refuses a
public-prefixed credential by name (`vite.pilot.config.ts`) and the artifact gate refuses it again
(`scripts/ci/verify-build.mjs`), so this is enforced at the build boundary rather than by review.

## 4. What an agent may and may not do

- **May**: run every local gate, edit source, migrations, tests, and docs, commit one concern at a
  time, and push branches.
- **May not**: write to the hosted Supabase project, deploy to production, create or rotate a
  credential, or place a secret anywhere in the repository.
- **Must**: treat a `BLOCKED` row as a reportable state, with the owner named. Never stub a
  credential, skip a gate, or weaken an assertion to turn `BLOCKED` into green. A false green is
  worse than a named blocker ([`AGENTS.md`](../../AGENTS.md) §3–§5).

## 5. When blocked

Write the blocker down in the same shape every time, so the next agent inherits state rather than a
question:

```text
BLOCKED  <capability>  needs <credential or decision>  held by <owner>  unblocks <gate id>
```

Then continue with work that does not depend on it. `docs/release-readiness.md` is the canonical list
of gates and their current state; `OWNER_ACTIONS.md` is the human-owned queue.
